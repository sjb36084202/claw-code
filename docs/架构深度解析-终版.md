# claw-code 架构深度解析：一份真正读懂代码的说明书

> 项目：https://github.com/instructkr/claw-code
> 分析人：天天变的更有钱 AI 助手

---

## 先说清楚：它到底是什么

很多人看到 GitHub 50K stars 的标题，以为这是一个"更好用的 Claude CLI"。

**不。这是对它最大的误解。**

从代码里读到的真实定位是：**一个通用的 AI Agent 运行时引擎。**

什么叫"引擎"？

想象一台汽车发动机。你加油（输入 prompt），发动机内部爆炸做功（LLM 推理 + 工具调用），能量传递到轮胎（输出结果）。同一台发动机，可以装进轿车、卡车、轮船——只要接口对就行。

claw-code 就是这样：它的核心 `ConversationRuntime` 是一个泛型结构，只要传入的 `ApiClient`（API 客户端）和 `ToolExecutor`（工具执行器）满足接口约定，一台"发动机"就能驱动任何 LLM、执行任何工具链、完成任何任务。

这就是它最核心的架构思想——**而不是什么"能联网搜索"或者"能执行 Bash 命令"。**

## 二、"一天的生活"：从你敲下命令到看到结果，代码是怎么跑的

### 场景：你在一个 Node.js 项目里执行 `./claw "帮我添加一个登录功能"`

**第一步（9ms）：解析参数，启动 REPL**

`main.rs` 解析你的输入：
- `--model sonnet` → 翻译成 `claude-sonnet-4-6`
- 发现没有子命令 → 启动交互式 REPL
- 找到当前目录 → `init.rs` 检测到 `package.json` → 这是个 Node.js 项目

**第二步（0ms）：组装系统提示词**

`prompt.rs` 启动 CLAUDE.md 发现流程：
- 从当前目录向上找 `CLAUDE.md` → 没找到
- 查找 `.claude.json` 配置 → 没找到
- 使用默认系统提示词

**第三步（你的输入进入）：构建对话请求**

`conversation.rs` 把你的输入打包：
```rust
MessageRequest {
    model: "claude-sonnet-4-6",
    max_tokens: 64_000,
    messages: [
        { role: "user", content: "帮我添加一个登录功能" }
    ],
    system: "你是 Claude...",
    tools: [ /* 15 个工具的 JSON Schema 定义 */ ],
    stream: true,  // ← 必须 SSE 流式
}
```

**第四步（SSE 连接建立）：Claude 开始"打字"**

`client.rs` 通过 SSE 连接发送请求，`sse.rs` 实时解析返回的事件流：

```
事件1: ContentBlockDelta(TextDelta) → "好的，我来帮你..."
事件2: ContentBlockDelta(TextDelta) → "首先让我看看项目结构"
事件3: ContentBlockDelta(InputJsonDelta) → {"path":".","pattern":"**/*.{js,ts}"}  // 模型调用 glob_search
事件4: MessageStop
```

**第五步（工具执行）：从理解到行动**

模型说"让我看看项目结构"的同时，调用了 `glob_search` 工具。

`conversation.rs` 立刻拦截这个调用：

```
权限检查 → 权限模式是 DangerFullAccess，glob_search 要求 ReadOnly → 通过
PreToolUse Hook → 没配置 → 跳过
执行工具 → glob_search 工具查找所有 .js 和 .ts 文件
PostToolUse Hook → 没配置 → 跳过
结果注入 → 把搜索结果塞回 messages，继续 SSE 流
```

**第六步（SSE 继续）：Claude 看到结果，决定下一步**

Claude 看到了项目结构，现在要创建 `login.js` 文件：

```
事件: ContentBlockDelta(InputJsonDelta) → {"path":"src/login.js","content":"..."}
```

这次是 `write_file` 工具，**要求 `DangerFullAccess` 权限**。

```
权限检查 → DangerFullAccess = DangerFullAccess → 通过
PreToolUse Hook → 没配置
执行 write_file → 写入了 src/login.js
→ 同时生成了 structured patch（精确的修改位置）
→ 同时调用 git diff 生成变更摘要
PostToolUse Hook → 没配置
```

**第七步：Claude 输出最终回复**

```
事件: ContentBlockDelta(TextDelta) → "已完成！我为你创建了 src/login.js，包含..."
事件: ContentBlockDelta(TextDelta) → "主要改动：\n1. 添加了 validateEmail 函数\n2. 添加了 hashPassword..."
事件: MessageStop → 对话轮次结束
```

**第八步（对话结束）：会话保存 + 用量统计**

`usage.rs` 记录了本次消耗：
```
Input tokens: 3,847
Output tokens: 1,203
Estimated cost: $0.08
```

如果对话很长，`compact.rs` 会自动介入——超过 20 万 tokens 时，把早期的对话聚合成摘要，保留最近的 4 条消息，节省后续费用。

## 三、五个真正体现架构优越性的设计

### 3.1 泛型 Trait 系统：让"发动机"可以换发动机

这是整个代码最精妙的设计，也是 Rust 比 TypeScript 优越的核心体现。

在 `conversation.rs` 里，核心结构体是这样的：

```rust
pub struct ConversationRuntime<C, T>
where
    C: ApiClient,     // 只要满足"能发请求、能收 SSE 流"这个约定
    T: ToolExecutor,  // 只要满足"能按名字执行工具"这个约定
```

这个 `<C, T>` 是什么意思？

**普通 TypeScript 代码**的调用是固定的：
```typescript
// 你只能这样用
const client = new AnthropicClient();
const runtime = new Runtime(client, executor);
```

**claw-code 的 Rust 泛型**可以这样用：
```rust
// 生产环境：真实的 Anthropic API
let client = AnthropicClient::new();
let executor = LocalToolExecutor::new();

// 测试环境：Mock 客户端
let client = MockApiClient::returning("login done");
let executor = MockToolExecutor::always_success();

// 远程环境：通过网络的 API 客户端
let client = RemoteApiClient::new("https://api.example.com");

// 同一个 Runtime，任意替换
let runtime = ConversationRuntime::new(client, executor);
```

这就是"发动机可以换发动机"的意思——**同一个结构体，编译时就确定了具体类型，没有运行时开销**，因为 Rust 的泛型是零成本抽象。

**这对产品意味着什么？**
- 未来可以接入 OpenAI、Gemini 任何模型
- 工具执行器可以本地、远程、沙箱任意切换
- 测试时不需要真正调用 API，直接 mock 结果
- 这不是过度设计——这是一个真正的框架应该有的基础能力

### 3.2 自动压缩：让 AI 拥有"长期记忆"

Claude 的上下文窗口是有限的。聊了几百轮之后，历史消息会把窗口填满，Claude 就"失忆"了。

大多数 AI CLI 的解决方案：直接截断前面，只留最近的。

**claw-code 的解决方案（compact.rs）：**

当输入 tokens 超过 20 万时（可通过环境变量配置），系统会自动：
1. **保留最近 4 条消息**（最新的上下文）
2. **把更早的所有消息聚合成一条摘要**
3. 摘要格式包含 `<analysis>`（分析过程）和 `<summary>`（关键结论）

```xml
<analysis>用户请求添加登录功能。Agent 执行了以下操作：1) 使用 glob_search 扫描项目结构，2) 使用 write_file 创建 src/login.js，3) 使用 write_file 创建 src/login.test.js</analysis>
<summary>项目根目录为 src/，主入口为 src/index.js，使用 Express。已创建 src/login.js（validateEmail + hashPassword），已创建单元测试文件。</summary>
```

更聪明的是：继续对话时，Claude 不会被复述"我们之前聊了什么"——直接继续。背后注入的消息是：

> "Continue the conversation from where it left off without acknowledging the summary, do not recap what was happening."

这意味着：**即使聊了 1000 轮，Claude 始终能以"记得"的方式服务**，而不是每次都得重新理解上下文。

**这解决的是什么问题？**
- 长时间 Pair Programming 的上下文丢失
- 大型重构过程中的历史记忆
- 复杂调试场景下的上下文连续性

### 3.3 Linux 沙箱 + namespace 隔离：让 AI 执行命令但不失控

AI 能执行 Bash 命令——这是强大能力的来源，也是最大的安全隐患。

大多数 AI CLI 对此的解决方案：**靠权限模式限制**（只读模式不许执行写操作）。

**claw-code 的解决方案（bash.rs + sandbox.rs）：** 不仅仅限制"能做什么"，还限制"能做到什么程度"。

```rust
pub struct BashCommandInput {
    command: String,                      // 要执行的命令
    timeout: Option<u64>,                 // 超时限制（秒）
    run_in_background: Option<bool>,    // 后台运行？
    dangerouslyDisableSandbox: Option<bool>,  // 跳过沙箱？
    namespace_restrictions: Option<bool>,    // Linux namespace 隔离
    isolate_network: Option<bool>,           // 禁用网络访问
    filesystem_mode: Option<FilesystemIsolationMode>,
    // workspaceOnly = 只能读写当前项目目录
    // allowList = 只能读写白名单目录
    // off = 完全访问
}
```

当 `namespace_restrictions: true` 时，Rust 代码会构建一个 `unshare` 命令：
```bash
unshare --pid --mount --net --ipc --cgroup \
  --map-root-user \
  chroot /path/to/workspace \
  bash -c "user's command"
```

**这意味着什么？**
- `ls /` 在沙箱里看不到真实根目录，只能看到项目目录
- `curl` 在网络隔离模式下完全无法连接外部
- 即使 AI 被引导执行 `rm -rf /`，在沙箱里也只能删项目文件
- 这些限制是**内核级别**的，不是代码检查能做到的

这就是为什么 `dangerouslyDisableSandbox` 要特意用 `dangerously` 开头命名——这是给那些"完全信任 AI、完全知道自己要干什么"的高级用户的警告。

### 3.4 Python 快照系统：用代码本身做规格说明书

这是 claw-code 最独特的设计哲学，业界罕见。

项目里有 66 个 Python 文件，但不是用来"替代 TypeScript"的——它们是**活的规格说明书**。

```
src/reference_data/
├── commands_snapshot.json   ← 从 TypeScript 源码提取了 207 条命令
├── tools_snapshot.json       ← 从 TypeScript 源码提取了 184 条工具
└── subsystems/              ← 33 个子系统的目录结构快照
    ├── assistant.json
    ├── hooks.json
    ├── plugins.json
    ├── services.json
    └── ...（共 33 个）
```

`parity_audit.py` 会自动对比：

```
根文件覆盖率: Python 28/31 (90%)
子系统覆盖率: 33/33 (100%)
命令条目: Rust 15 / TypeScript 207 (7%)
工具条目: Rust 15 / TypeScript 184 (8%)
```

**这样做为什么聪明？**

传统软件开发中，规格说明书和代码是两份文件，久了就会不一致。

claw-code 把这个关系翻转了：**Python 快照记录"目标是什么"，Rust 实现"目标现在完成了多少"**。每次分析 TypeScript 源码更新，快照自动更新——Rust 开发者永远有清晰的路线图，不会"不知道还缺什么"。

### 3.5 MCP 协议：不是插件系统，是一个标准

大多数工具平台都有自己的插件 API ——但这意味着每接入一个新工具，代码里就要加一堆 if-else。

claw-code 选择支持 **MCP（Model Context Protocol）**——一个开放的行业标准。

```rust
pub enum McpTransport {
    Stdio(McpStdioTransport),     // 子进程（最常用）
    Sse(McpRemoteTransport),       // SSE 远程
    Http(McpRemoteTransport),     // HTTP 请求
    WebSocket(McpRemoteTransport),// WebSocket
    Sdk(McpSdkTransport),          // SDK 集成
    ClaudeAiProxy(McpClaudeAiProxyTransport),  // 代理模式
}
```

这意味着：**任何实现了 MCP 协议的工具，claw-code 都能直接用**——不需要写专门的适配器。连接数据库工具、GitHub API 工具、搜索工具，都是配置文件里加一行：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "./"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"]
    }
  }
}
```

**这对产品的意义：**
- 工具扩展不依赖代码更新，改配置文件就行
- MCP 生态在快速增长，今天能用，明天会有更多
- 与 Anthropic、OpenAI 等主流 AI 平台的方向一致

## 四、技术架构的深层逻辑：为什么这样做

### 4.1 为什么选 Rust 而不是 Go 或 TypeScript？

很多人问：Rust 门槛这么高，为什么不用 Go？

答案在代码里：**一个 AI Agent 的运行时，每秒可能要执行几十个工具调用，每个工具调用都可能产生文件操作、网络请求。**

Go 的 GC（垃圾回收）在高频率工具调用场景下会产生不可预期的停顿——你无法告诉用户"这次工具调用慢是因为 GC 在回收内存"。

Rust 的所有权系统 + 零 GC = 所有内存分配都是确定性的，**工具调用的延迟是可预测的，不会突然卡顿**。

加上 Rust 编译成原生码，冷启动 < 100ms——Go 或 Java 做不到这个速度。

### 4.2 为什么 OAuth 选 PKCE 而不是简单 token？

认证代码（oauth.rs）用了 OAuth 2.0 的 **PKCE（Proof Key for Code Exchange）** 扩展。

普通的 OAuth 流程：客户端把 client_secret 发给认证服务器。

PKCE 流程：**不存储 client_secret**，每次认证时动态生成一个随机的 code_verifier，只有知道这个 verifier 的客户端才能换 token。

这对桌面 CLI 特别重要——**代码是公开的，不能存 secret**。PKCE 让整个认证流程即使被旁观也安全。

### 4.3 为什么 session 存储选 JSON 而不是数据库？

代码里 session 的存储是：

```rust
pub fn save_to_path(&self, path: impl AsRef<Path>) -> Result<(), SessionError> {
    fs::write(path, self.to_json().render())?;
}
```

写一个 JSON 文件，读出来就恢复。

不用数据库的理由：
1. **零依赖**：不要求用户装了 PostgreSQL 或 Redis
2. **零运维**：文件在 `~/.claude/sessions/` 下，用户自己备份
3. **足够快**：SSTable 级别的本地文件读取，远快于网络数据库
4. **可移植**：一个 JSON 文件，复制到任何机器都能恢复

| 沙箱安全 | 基础权限检查 | 无 | **namespace 内核级隔离** |
| 插件扩展 | 专有 API | 专有 API | **MCP 开放标准** |
| 长期会话 | 手动 compact | 无 | **自动压缩（20万token）** |
| 架构灵活性 | 硬编码 | 硬编码 | **泛型 trait，可替换组件** |
| 许可证 | 需官方授权 | Apache 2.0 | **MIT，开源免费** |

**最值得学的三点：**
1. **泛型 trait 抽象** → 不是"写一个 AI CLI"，而是"构建一个 AI 运行时框架"
2. **Python 快照做规格** → 代码即文档，文档即测试，覆盖率永远准确
3. **SSE 流式优先** → 不是等完整响应，是实时流输出，交互体验完全不一样
