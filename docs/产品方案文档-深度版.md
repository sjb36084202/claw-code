## 一、项目本质：从代码中读到的真实定位

### 1.1 它是什么，不是做什么

阅读 `rust/crates/rusty-claude-cli/src/main.rs` 的 `run()` 函数和 `CliAction` 枚举，核心入口只有：

```rust
enum CliAction {
    DumpManifests,           // 导出清单
    BootstrapPlan,           // 打印引导计划
    PrintSystemPrompt { ... },// 打印系统提示词
    Version,                 // 版本
    ResumeSession { ... },   // 恢复会话
    Prompt { ... },          // 单次 prompt（非交互）
    Login,                   // OAuth 登录
    Logout,                  // 登出
    Init,                    // 初始化项目
    Repl { ... },            // 交互式 REPL（主入口）
    Help,
}
```

**这不是一个通用 CLI 框架。** 它是专为 Claude（大语言模型）设计的**交互式 Agent Harness**——驱动 AI 模型执行工具调用、管理会话状态、处理权限的运行时引擎。

从 `rust/crates/runtime/src/conversation.rs` 的 `ConversationRuntime` 可以清楚看到：

```rust
pub struct ConversationRuntime<C, T> {
    session: Session,           // 会话状态
    api_client: C,              // Anthropic API 客户端
    tool_executor: T,           // 工具执行器
    permission_policy: PermissionPolicy, // 权限策略
    system_prompt: Vec<String>, // 系统提示词
    max_iterations: usize,      // 最大迭代次数（默认 usize::MAX）
    usage_tracker: UsageTracker,// Token 用量追踪
    hook_runner: HookRunner,    // 钩子运行器
    auto_compaction_input_tokens_threshold: u32, // 自动压缩阈值
}
```

### 1.2 核心循环：Agent 的工作方式

从 `conversation.rs` 的 `run_turn()` 方法读到的 Agent 主循环：

```
用户输入
  ↓
组装 API 请求（system_prompt + messages）
  ↓
发送 SSE 流到 Anthropic API
  ↓
逐事件解析 SSE 流
  ├─ TextDelta → 实时输出文本
  ├─ ToolUse → 执行工具
  │    ├─ 权限检查（PermissionPolicy.authorize）
  │    ├─ PreToolUse Hook
  │    ├─ 执行工具（Bash/File/Search/Web等）
  │    ├─ PostToolUse Hook
  │    └─ 返回结果给模型
  └─ Usage → 记录 Token 消耗
  ↓
循环直到模型输出纯文本（无 ToolUse）
  ↓
可能触发自动压缩（auto_compact）
```

### 2.2 Bash 工具的深层实现（runtime/bash.rs）

这是代码中最复杂的工具实现（200+ 行），支持：

- **后台运行**：`run_in_background: true` → fork 子进程，不阻塞
- **沙箱执行**：调用 `build_linux_sandbox_command()`，支持 namespace 隔离
- **超时控制**：`timeout` 参数，通过 `tokio::time::timeout` 实现
- **网络隔离**：`isolate_network: true` → 禁用网络
- **文件系统隔离模式**：`filesystem_mode: "workspace-only" | "allow-list" | "off"`
- **异步执行**：使用 Tokio 异步运行时
- **Background Task ID**：后台任务可被追踪和恢复

**关键数据结构（从 BashCommandOutput 读出）：**

```rust
pub struct BashCommandOutput {
    pub stdout: String,
    pub stderr: String,
    pub interrupted: bool,           // 是否被中断
    pub is_image: Option<bool>,      // 输出是否为图片
    pub background_task_id: Option<String>, // 后台任务 ID
    pub sandbox_status: Option<SandboxStatus>, // 沙箱状态
    pub git_diff: Option<serde_json::Value>,    // git diff
    pub persisted_output_path: Option<String>,  // 持久化输出路径（大输出）
}
```

### 2.3 文件操作的深层实现（runtime/file_ops.rs）

文件工具是第二复杂的模块（470+ 行）：

**read_file 特点：**
- 支持行号分片读取（offset + limit）
- 自动计算总行数（total_lines）
- 返回文件内容的结构化表示（TextFilePayload）

**write_file 特点：**
- 自动生成 unified diff 和 structured patch（hunk 格式）
- 自动检测 git 仓库，生成 git diff
- 检测文件是否被用户手动修改（user_modified flag）
- 支持 `replace_all` 批量替换

**edit_file 特点：**
- 精确 oldString → newString 替换
- 支持 `replace_all: true` 全局替换
- 保留原始文件内容（original_file 字段）
- 生成结构化 patch 供模型确认

### 2.5 权限系统（runtime/permissions.rs）

**五种权限模式（从代码枚举读出）：**

```rust
pub enum PermissionMode {
    ReadOnly,          // 仅读
    WorkspaceWrite,    // 工作目录写
    DangerFullAccess,  // 完全访问
    Prompt,            // 每次询问
    Allow,             // 允许（内部用）
}
```

**权限检查逻辑（authorize 方法）：**
1. 如果当前模式是 `Allow` 或 `>= required_mode` → 直接放行
2. 否则弹出交互式提示让用户决策
3. 用户可选择 Allow 或 Deny（带原因）

**默认权限：** 从 `main.rs` 读到默认是 `DangerFullAccess`，与 Claude Code 一致。

**自动压缩机制（从代码分析）：**

- 摘要格式：使用 `<analysis>` + `<summary>` XML 标签结构
- 后续继续对话时不复述摘要内容，直接继续

## 八、关键设计哲学

### 8.1 渐进式迁移

不是一次性重写，而是：
1. Python 作为参考快照（验证对 TS 源码的理解）
2. Rust 作为生产实现（从零设计，利用 Rust 优势）
3. 两者通过 `compat-harness` crate 桥接（提取 TypeScript 清单）

### 8.2 Trait 抽象

Rust 使用 trait 绑定实现灵活组合：

```rust
pub trait ApiClient {
    fn stream(&mut self, request: ApiRequest) -> Result<Vec<AssistantEvent>, RuntimeError>;
}

pub trait ToolExecutor {
    fn execute(&mut self, tool_name: &str, input: &str) -> Result<String, ToolError>;
}
```

→ 可以替换 API 实现（MCP → Anthropic → OpenAI）
→ 可以替换工具执行器（本地 → 远程 → 沙箱）
